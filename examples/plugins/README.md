# Примеры плагинов

Данная папка содержит практические примеры плагинов для Vibee, демонстрирующие различные паттерны и возможности системы плагинов.

## 📁 Структура

```
examples/
├── basic-provider/      # Пример провайдера данных
├── basic-scene/         # Пример сцены (визарда)
├── basic-command/       # Пример команд бота
└── middleware/          # Пример middleware
```

## 🚀 Быстрый старт

### 1. Использование примера

```typescript
// В вашем персонаже (src/character.ts)
import { basicCommandPlugin } from '../examples/plugins/basic-command';
import { basicProviderPlugin } from '../examples/plugins/basic-provider';
import { basicScenePlugin } from '../examples/plugins/basic-scene';
import { middlewarePlugin } from '../examples/plugins/middleware';

export const vibeeCharacter: Character = {
  name: 'Vibee',
  plugins: [
    '@elizaos/plugin-bootstrap',
    basicCommandPlugin,   // Добавляем команды
    basicProviderPlugin,  // Добавляем провайдер
    basicScenePlugin,     // Добавляем сцены
    middlewarePlugin      // Добавляем middleware
  ],
  // ...
};
```

### 2. Тестирование примера

```bash
# Запуск тестов примера
npm test -- basic-command

# С интерактивным режимом
npm test -- --watch basic-command
```

### 3. Адаптация под свои нужды

1. Скопируйте нужный пример в папку `src/`
2. Переименуйте файлы
3. Измените логику под свои требования
4. Добавьте в персонажа
5. Протестируйте

## 📚 Примеры по типам

### 1. Basic Provider (`basic-provider/`)

**Что демонстрирует:**
- Создание провайдера данных
- Предоставление контекстной информации
- Работу с базой данных
- Кэширование данных

**Основные компоненты:**
- `timeProvider` - провайдер времени
- `userStatsProvider` - провайдер статистики пользователя

**Использование:**
```typescript
// В действии можно получить данные провайдера
const time = state.values.currentTime;
const messageCount = state.values.messageCount;
```

**Ключевые особенности:**
- Возвращает данные в формате `{ text, values, data }`
- Автоматически вызывается при каждом сообщении
- Данные доступны в state.values

---

### 2. Basic Scene (`basic-scene/`)

**Что демонстрирует:**
- Создание многошаговых визардов
- Управление состоянием сцены
- Последовательное взаимодействие с пользователем
- Service для управления сценами

**Основные компоненты:**
- `SceneManagerService` - сервис управления сценами
- `START_SCENE` - запуск сцены
- `SCENE_INPUT` - обработка ввода
- `STOP_SCENE` - остановка сцены

**Использование:**
```
Пользователь: "начать сцену"
Бот: "Добро пожаловать! Шаг 1 из 3: Введите ваше имя"
Пользователь: "Алексей"
Бот: "Отлично! Шаг 2 из 3: Какой ваш любимый цвет?"
...
```

**Ключевые особенности:**
- Сохраняет состояние между шагами
- Обрабатывает ошибки и некорректный ввод
- Позволяет остановить сцену в любой момент

---

### 3. Basic Command (`basic-command/`)

**Что демонстрирует:**
- Создание команд бота
- Обработку различных типов команд
- Работу с базой данных для статистики
- Валидацию команд

**Основные компоненты:**
- `HELP_COMMAND` - справка по командам
- `TIME_COMMAND` - показ времени
- `STATS_COMMAND` - статистика пользователя
- `ABOUT_COMMAND` - информация о боте
- `ECHO_COMMAND` - повторение текста

**Использование:**
```
/help
/time
/stats
/about
echo Привет!
```

**Ключевые особенности:**
- Поддерживает команды с `/` и без
- Синонимы для каждой команды
- Хранит статистику в базе данных
- Информативные ответы с эмодзи

---

### 4. Middleware (`middleware/`)

**Что демонстрирует:**
- Создание middleware для перехвата запросов
- Аутентификацию и авторизацию
- Rate limiting (ограничение частоты)
- Логирование запросов
- Валидацию входных данных

**Основные компоненты:**
- `AuthService` - сервис авторизации
- `RateLimitService` - сервис ограничения запросов
- `LoggingService` - сервис логирования
- Цепочка middleware для `MESSAGE_RECEIVED`

**Использование:**
```
Middleware автоматически срабатывает при получении сообщения:
1. Валидация - проверяет корректность
2. Rate Limit - ограничивает частоту
3. Auth - проверяет авторизацию
4. Logging - логирует запрос
```

**Ключевые особенности:**
- Перехватывает все сообщения
- Не блокирует основной поток
- Добавляет метаданные в context
- Настраивается через environment

## 🛠 Инструменты и утилиты

### Создание собственного плагина

```bash
# С помощью генератора
npm run create:plugin -- --name=my-plugin --type=command

# Или вручную
touch src/my-awesome-plugin.ts
```

### Отладка

```typescript
// Включение debug логов для плагина
DEBUG=basic-command:* npm run dev

// Или для всех плагинов
DEBUG=vibee:* npm run dev
```

### Тестирование

```typescript
// Пример теста для плагина
import { describe, expect, it } from 'bun:test';
import { basicCommandPlugin } from '../basic-command';

describe('Basic Command Plugin', () => {
  it('should register actions', () => {
    expect(basicCommandPlugin.actions).toBeDefined();
    expect(basicCommandPlugin.actions?.length).toBeGreaterThan(0);
  });
});
```

4. **Напишите middleware** для фильтрации матов

## 💡 Советы

### Производительность

- Кэшируйте данные в Provider
- Используйте async/await без блокировки
- Ограничивайте размер логов
- Реализуйте cleanup в Service.stop()

### Безопасность

- Валидируйте входные данные
- Проверяйте авторизацию
- Логируйте важные события
- Обрабатывайте ошибки gracefully

### Читаемость кода

- Используйте понятные имена
- Добавляйте JSDoc комментарии
- Разделяйте логику на функции
- Пишите тесты

### Отладка

- Используйте structured logging
- Добавляйте контекст в логи
- Тестируйте edge cases
- Мокайте внешние зависимости
